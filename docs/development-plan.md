# PulseCast（怦然）发展路线图

> 编制日期：2026-07-24 · 基于 v0.7 代码审查后的全局演进规划
> 核心命题：**让更多主播用得上、用得顺、用得好看**

| 维度 | 评分 | 瓶颈 |

## 一、Phase 1 · 顺手（v0.8）—— 把 5 分钟设置压到 30 秒

> 目标：一个从未用过的主播，打开 App → 看到 OBS 里有心率，全程不超过 30 秒。

### 1.1 一键 OBS 注入（最高优先）

**现状**：用户需手动复制 URL → 打开 OBS → 添加浏览器源 → 粘贴 → 调尺寸。

**方案**：Tauri 桌面端内嵌 OBS WebSocket 协议（obs-websocket v5），实现：
- 自动发现本机 OBS（扫描 `ws://localhost:4455`，OBS 28+ 默认开启）
- 一键「添加到 OBS」按钮：自动创建浏览器源 + 设好 URL/尺寸/透明背景
- 若 OBS 未开启 WebSocket，弹出图文引导（3 步截图）

**技术要点**：
- Rust 侧新增 `obs_ws.rs` 模块，用 `tokio-tungstenite` 连 OBS WebSocket
- 协议：`CreateInput`（类型 `browser_source`）+ `SetInputSettings`
- 不引入 OBS 依赖，纯 WebSocket JSON 通信
- 降级：连不上就回退到"复制 URL"模式

### 1.2 FTUE 重做

**现状**：3 步向导，但步骤 3 只是一段 URL 文字。

**方案**：
- 步骤 1：设备连接（保持，优化扫描速度）
- 步骤 2：实时预览（保持，增加样式切换预览）
- 步骤 3：**自动检测 OBS → 一键注入 / 图文引导二选一**
- 步骤 4（新增）：「开播检查清单」—— OBS 源是否在线、心率是否在跳、阈值是否设好

### 1.3 系统托盘 + 全局热键

**现状**：`tray-icon` feature 已声明但无逻辑。

**方案**：
- 托盘图标：显示当前 BPM 数字（macOS 菜单栏 / Windows 系统托盘）
- 右键菜单：切换模拟/真实源、打开设置、退出
- 全局热键：`Ctrl+Shift+H` 隐藏/显示心率叠加（直播中临时关闭）

### 1.4 配置零感知

- 首次启动自动生成 token，用户无需知道 token 的存在
- OBS 浏览器源 URL 自动带 token（通过一键注入或剪贴板）
- 记住上次连接的设备，下次启动自动重连

## 二、Phase 2 · 低占用（v0.9）—— 让 OBS 不掉帧

> 目标：PulseCast 全部组件（服务 + 叠加 + 插件）CPU 占用 < 2%，GPU 占用 < 1%。

### 2.1 OBS 连接池（单例 WS 管理器）

**现状**：每个 OBS 源/滤镜各开一条 WS 连接 + 一个线程。3 个源 = 3 条 TCP + 3 个 pthread。

**方案**：
- 进程内单例 `pc_ws_manager`：一条 WS 连接，引用计数分发
- 源/滤镜创建时 `pc_ws_acquire()`，销毁时 `pc_ws_release()`
- 最后一个释放时关闭连接
- 线程数从 N 降到 1

### 2.2 ECG 渲染降频

**现状**：`requestAnimationFrame` 60fps 持续运行，即使 OBS 以 30fps 推流。

**方案**：
- OBS 浏览器源：检测 `obs-websocket` 的帧率，匹配渲染频率
- 降级策略：页面不可见时暂停（v0.7 已实现）；低性能模式降到 15fps
- ECG 波形用 `OffscreenCanvas` + `Worker` 离屏渲染，主线程零阻塞

### 2.3 Glow 滤镜 GPU 优化

**现状**：5×5 邻域采样（25 次 texture sample），4K 下 GPU 压力大。

**方案**：
- 两遍分离式高斯（水平 5 + 垂直 5 = 10 次采样，效果等价）
- 降采样：先在 1/4 分辨率做 glow，再叠加回原图
- 添加「性能模式」开关：关闭 glow 仅保留抖动

### 2.4 Rust 服务端瘦身

- `config.rs`：`std::fs` → `tokio::fs`（消除异步上下文中的同步阻塞）
- broadcast channel 容量：16 → 动态（`subscriber_count * 2`）
- 模拟源 LCG → `fastrand`（更快、更小）
- 编译优化：`opt-level = "z"` + `strip` + `lto`（已部分实现）

## 三、Phase 3 · 好看（v1.0）—— 让心率成为直播间的视觉亮点

> 目标：叠加样式从"能用"到"想用"，让主播主动截图分享。

### 3.1 叠加样式引擎

**现状**：3 种硬编码样式（pill / ecg / number），颜色/大小/位置不可调。

**方案**：
- 引入样式配置面板（Tauri 设置页）：
  - 颜色选择器（主色 / 背景 / 文字）
  - 字体大小 / 圆角 / 透明度滑块
  - 位置预设（左上 / 右上 / 底部居中 / 自定义拖拽）
- 样式以 JSON 描述，obs-overlay.html 动态渲染
- 预设主题：「电竞红」「极简白」「赛博霓虹」「像素复古」

### 3.2 动态特效库

- 心跳粒子：每次心跳从心率数字散发粒子（Canvas 2D，轻量）
- 呼吸光环：心率越高，光环脉冲越快（CSS animation + JS 驱动）
- 里程碑动画：心率突破阈值时全屏特效（烟花 / 闪电 / 警报灯）
- 所有特效 GPU 加速（`will-change: transform`），不阻塞 OBS 编码线程

### 3.3 OBS 原生插件视觉升级

- 心率源：支持自定义字体 / 描边 / 阴影 / 渐变填充
- 发光滤镜：颜色可自定义（不再硬编码 #FF4D6D）
- 新增「心率仪表盘」源：半圆表盘 + 指针 + 区间色带（GPU 渲染）

### 3.4 设计系统固化

- `design-tokens.css` 升级为完整的 Design Token JSON（支持主题切换）
- 所有前端页面统一使用 Token，消除硬编码色值
- 暗色 / 亮色 / OBS 透明三套主题

## 五、Phase 5 · 架构演进（v1.x 远期）

### 5.1 前端框架迁移

**现状**：~1200 行 vanilla JS，状态管理靠手动 DOM，settings/mobile 逻辑重复。

**方案**：迁移到 Svelte（轻量、编译时、零运行时）
- 路径：settings → mobile → ftue（obs-overlay 保持独立，OBS 兼容性优先）
- 收益：状态管理自动化、组件复用、类型安全（TypeScript）
- 风险：OBS 浏览器源对现代 JS 的支持（Chromium 内核，Svelte 编译产物兼容）

### 5.2 插件化输出

- 服务端 trait 抽象：`OutputPlugin`（OSC / OBS WebSocket / Twitch / YouTube）
- 当前 OSC 和 OBS 场景切换硬编码在 lib.rs，拆分为独立插件
- 为远期「直播辅助套件」预留接口（但不提前实现）

### 5.3 移动端原生化

- 短期：PWA（当前方案，修好 token 后基本可用）
- 中期：Tauri Mobile（配置已存在，待 Tauri 2 mobile 稳定）
- 长期：独立 iOS/Android App（SwiftUI / Compose），BLE 直连 + 本地服务

### 5.4 安全加固

| 阶段 | 措施 | 状态 |
|------|------|------|
| Phase 1 | WS token + Origin guard | ✅ v0.7 |
| Phase 2 | /api/* token 校验 | ✅ v0.7 |
| Phase 3 | CSP 策略配置 | 待做 |
| Phase 4 | token 改用 `getrandom`/`OsRng` | 待做 |
| Phase 5 | OBS 插件支持 token 参数（设置面板） | 待做 |

## 八、不可违背的约束（继承自产品方向定义）

1. **本地优先。** 不引入云端依赖，不上传心率数据，不做账号系统。
2. **免费开源。** MIT 许可证，所有代码公开。
3. **OBS 兼容。** 核心体验围绕 OBS 构建，浏览器源是最低门槛入口。
4. **蓝牙直连。** 不依赖手机 App 中转。
5. **一人节奏。** 不套团队流程，修完 → 测 → 发 → 收反馈。
6. **性能预算。** 任何新功能不得使 CPU 占用增加超过 0.5%。
