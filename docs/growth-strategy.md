# PulseCast（怦然）推广策略与获客方案

> 版本：v1.2 | 日期：2026-07-22 | 负责人：增长运营
> 产品状态：v0.1.0 Alpha（功能原型完成，尚未公开发布）
>
> **v1.2 重验说明（workspace_drift 追加修复）**：综合评审重验（docs/comprehensive-review-report.md v1.1）新发现 3 项技术缺口，影响推广前置条件判定：
> 1. **OBS 插件 WS 路径不匹配（"/" vs "/ws"）**：插件连不上新版服务端 → P0 渠道"OBS 插件市场"演示链路断裂
> 2. **mobile.js 未适配 token 认证**：手机遥控器功能不可用 → 推广视频少一个差异化卖点
> 3. **HTTP API 层缺 token 校验（Origin guard 可绕过）**：安全叙事不完整 → 影响"隐私安全"核心对比优势
>
> 三项合计约 5h 工作量，为发布前**硬性前置条件**。Phase 0 时间线需增加修复验证环节。
>
> **v1.1 重验说明**：基于综合评审（docs/comprehensive-review-report.md）结论和代码库最新状态重验。以下原策略中标记为"风险"或"待完成"的项目已落地：WS token 认证 + HTTP Origin 校验（安全加固）、GitHub Actions CI/CD（ci.yml + release.yml）、CONTRIBUTING.md + Issue 模板。推广前置条件已基本满足，可进入 Phase 0 执行。

## 一、目标用户画像细分

### 1.1 游戏主播（优先级：★★★★★）

| 维度 | 描述 |
|------|------|
| 典型场景 | 恐怖游戏（心跳加速名场面）、竞技对战（紧张决胜局）、抽卡/开箱（期待感） |
| 核心需求 | 让观众看到自己"真的紧张了"，增强互动娱乐性 |
| 痛点 | 现有方案需要额外硬件+复杂配置；或依赖云端有延迟和隐私风险 |
| 活跃平台 | B站直播、斗鱼、虎牙、抖音直播、Twitch |
| 规模估算 | 中文游戏主播（月活开播）约 200-500 万人；有"心率展示"需求的约 5-10% |
| 转化钩子 | "观众看到你心跳飙到 160 的弹幕会炸" |

### 1.2 运动健身主播（优先级：★★★★☆）

| 维度 | 描述 |
|------|------|
| 典型场景 | 健身直播、跑步/骑行直播、瑜伽/HIIT 课程 |
| 核心需求 | 实时展示运动强度，证明"真的在练"，增强专业感和信任度 |
| 痛点 | 运动手表数据无法直接叠加到直播画面；需要手机中转、延迟大 |
| 活跃平台 | 抖音直播、快手直播、Keep、小红书直播、YouTube Fitness |
| 规模估算 | 健身类直播创作者约 50-100 万人（中文）；海外约 30-80 万人 |
| 转化钩子 | "心率区间实时显示，观众监督你的训练强度" |

### 1.3 聊天/IRL 主播（优先级：★★★☆☆）

| 维度 | 描述 |
|------|------|
| 典型场景 | 聊天互动、整蛊反应、表白/社死现场、吃播（辣度挑战） |
| 核心需求 | 增加"真实感"和娱乐性，心率成为互动梗 |
| 痛点 | 缺乏差异化工具，内容同质化严重 |
| 活跃平台 | 抖音、B站、快手、Twitch IRL |
| 规模估算 | 泛娱乐直播创作者基数最大（千万级），但心率需求渗透率极低（<2%） |
| 转化钩子 | "心率不会骗人——观众最爱看你心跳加速的瞬间" |

### 1.4 VTuber / 虚拟主播（优先级：★★★★☆）

| 维度 | 描述 |
|------|------|
| 典型场景 | VTuber 直播中展示"真实心跳"增加人设真实感；VRChat 社交 |
| 核心需求 | 将生理数据映射到虚拟形象（已支持 VRChat OSC）；OBS 叠加 |
| 痛点 | 现有 VTuber 工具链（VTube Studio、VMC 协议）缺乏心率集成 |
| 活跃平台 | B站虚拟主播区、YouTube VTuber、Twitch、VRChat |
| 规模估算 | 活跃 VTuber 约 5-15 万人（中日英）；VRChat 活跃用户约 10-30 万 |
| 转化钩子 | "让你的皮套拥有真实心跳——VRChat OSC 直连，零配置" |

### 1.5 用户优先级排序

1. **游戏主播**（需求最明确、场景最自然、传播性最强）
2. **VTuber**（技术契合度高、社区传播快、已有 VRChat 集成）
3. **运动健身主播**（刚需但竞品多、需突出本地无延迟优势）
4. **聊天主播**（基数大但需求弱、作为自然扩散群体）

### 2.2 优先级分层

**P0（首月核心渠道，集中 70% 精力）：**
- **B站**：游戏/虚拟主播区 UP 主合作 + 直播工具测评视频
- **OBS 论坛/插件市场**：作为 OBS 官方插件提交，获取精准搜索流量
- **抖音直播区**：短视频展示"心率叠加"效果，引导下载

**P1（第二月扩展，20% 精力）：**
- **即刻**：Build in Public 分享开发故事，获取种子用户和传播
- **Twitch/Reddit**：r/Twitch、r/livestreamfail、OBS subreddit
- **Discord**：VTuber 社区、直播工具社区、VRChat 社区

**P2（季度内覆盖，10% 精力）：**
- **小红书**：健身博主种草、直播设备推荐清单
- **YouTube**：英文教程视频、对比测评
- **Product Hunt**：配合正式版本发布，一次性爆发

### 2.3 渠道策略要点

**B站策略：**
- 投稿类型：工具测评（"5 款直播心率工具对比"）、效果展示（"恐怖游戏心跳 180"）、教程（"3 分钟配置心率直播"）
- 合作对象：1-10 万粉游戏/科技区 UP 主（性价比最高）
- 关键词布局：直播工具、OBS 插件、心率直播、直播特效

**OBS 插件市场策略：**
- 提交到 obsproject.com 官方插件目录
- 在 OBS 论坛发布 Release 帖，附 GIF/视频演示
- 利用 OBS 用户搜索"heart rate overlay"的自然流量
- 这是长期 SEO 流量入口，竞争极低

**抖音策略：**
- 15-30 秒短视频：展示"主播心跳飙升"的直播画面切片
- 评论区引导：置顶下载链接
- 标签：#直播工具 #主播必备 #OBS #心率直播

## 三、冷启动策略

| 阶段 | 动作 | 预期转化 |

| 第 3-4 周 | B站/抖音发布 2-3 条演示视频 | 50-150 下载 |

### 3.2 KOL 合作策略

**分层合作模型（零预算/低预算）：**

| 层级 | 粉丝量 | 合作方式 | 成本 | 预期效果 |
|------|--------|---------|------|---------|
| 微型 KOL | 1K-10K | 免费使用 + 自发分享 | 0 | 真实口碑，转化率高（5-15%） |
| 小型 UP 主 | 10K-100K | 提供定制功能/优先支持 | 0（时间成本） | 单条视频 500-5000 播放 |
| 中型 UP 主 | 100K-500K | 付费合作或联合开发 | ¥500-3000/条 | 单条 1-10 万播放 |
| 测评博主 | 不限 | 提供评测素材包 | 0 | 长尾搜索流量 |

**重点合作对象类型：**
- 直播工具/设备测评博主（如"直播设备推荐"类账号）
- 恐怖游戏主播（天然场景，心率飙升有节目效果）
- VTuber 技术向博主（VRChat 集成是独特卖点）
- 健身直播博主（运动心率是刚需）

### 3.3 直播工具测评博主策略

- 准备「评测素材包」：高清演示 GIF、对比视频、功能清单、FAQ
- 主动联系 10-20 位测评博主，提供免费 Pro 功能（如有）或定制支持
- 提供"对比测评"角度：vs Streamlabs 心率组件 vs 手动 OBS 配置 vs 云端方案
- 核心对比优势：本地无延迟、开源免费、零配置、隐私安全

### 5.2 用户反馈收集机制

**收集渠道：**
- GitHub Issues（Bug + Feature Request 模板）
- Discord #feedback 频道
- 应用内反馈入口（设置页 → 反馈）
- 社交媒体评论监控（B站、抖音、即刻）

**处理流程：**
1. 每日汇总新反馈（自动 + 人工）
2. 分类：Bug / 功能需求 / 体验问题 / 正面评价
3. 按 影响面 × 紧急度 排优先级
4. 每周同步给产品负责人
5. 公开 Roadmap 更新（GitHub Project Board），让用户看到反馈被采纳

**闭环原则：** 每条反馈都要有回应，哪怕是"已收到，排入规划"。

### 5.3 开源社区贡献者激励
